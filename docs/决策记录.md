# 决策记录

## 2026-11-06 接入 Undermind.ai 的 MCP

**背景**：要把 Undermind（学术文献检索）接进 DSH。官方 MCP server 是
`https://mcp.undermind.ai/mcp`，Streamable HTTP，**只支持用户级 OAuth**：
- 没有 API key / service account 兼容模式；
- Scope 固定为 `mcp`；
- 不支持动态客户端注册（DCR），只支持 CIMD 或预先注册的 client ID；
- access token 1 小时过期，refresh token 轮换，90 天不刷新连接失效。

**DSH 现状**：`@deepseek-ai/dsh-mcp-client` 是 DSH 内置的 MCP 桥，配置项只支持
`transport: stdio | streamable-http` + 静态 headers，**没有任何 OAuth 能力**。
所以不能直接在 cordis.patch.yml 里填 Undermind 的 URL。

**决策**：

1. **不写 DSH 插件，写一个 stdio 中继桥**。`dsh-mcp-client` 本来就会拉起 stdio 子进程，
   把 bridge 当 command 配进去，生命周期、重连、工具命名（`mcp__undermind__*`）全部
   复用内置桥，我们只补它缺的那一块：OAuth。
   备选方案（本地 HTTP 代理 + `transport: streamable-http`）被否掉：需要额外守护进程，
   还要解决「DSH 启动时桥还没起来」的顺序问题。
2. **client_id 用 CIMD，托管在 GitHub Pages**。这是最快、不需要等 Undermind 人工
   注册的路径。`client-metadata.json` 的 `client_id` 字段必须和发布 URL 完全一致；
   回调固定为 `http://127.0.0.1:53682/callback`。
   备选：邮件 support@undermind.ai 预注册（要等）；或已有 client_id（没有）。
3. **token 存在仓库的 `.state/tokens.json`**（0600、gitignore）。放 workspace 里是因为
   沙箱里调试方便；代价是这份文件不能提交、不能外发。
4. **桥自己处理 token 刷新**：请求前按 `expires_at` 预刷新，遇到 401 再强制刷新重试一次；
   刷新后的 refresh token 立刻落盘（轮换后旧 token 失效）。

**后果**：DSH 侧零改动，只加一条 profile patch；升级 DSH 不影响。bridge 用 Node 24
原生 fetch，无第三方依赖。风险点是 Undermind 的授权服务器对 CIMD 文档的抓取/校验
（必须是公网 HTTPS、`client_id` 与 URL 完全匹配），如果它不认 GitHub Pages，退回预注册。
